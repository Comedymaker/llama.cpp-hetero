# Q3和读取—复制分级流水线规划器

## 后续补测更新（同日）

已完成/staged-q23-calibration-20261024的Q2/Q3复制成本，staged默认源现为CPU4、7读1复制、计算后驱逐的1176条记录，不再缺测。8行规划见`multibit-staged-calibrated-20261024/n8/`：Q3=0、Q2=768，预测比值1.38407，状态not_reached_by_coordinate_search。不是已平衡，更不是全Q2质量最优。纯位宽实测整体Q2比例1.354、Q3比例1.522。下面关于Q2/Q3复制缺测、仅Q4回放的段落是实现初版时的历史记录，已被本更新取代。

直接运行`--route staged --upgrade-bit 3 --nodes 8 --output <新目录>`现可提取本轮Q2/Q3成本并规划。仍只有纯位宽端点，混合成本/调度属于插值，不能声称混合模型已经上手机实测。

## 已实现及边界

原Q2/Q4规划器默认入口、旧schema1成本表、旧selection.tsv和树初值输出均保留。新增明确的`--route direct|staged --upgrade-bit 3`入口使用独立schema2，不把旧加载成本表解释成Q3或复制成本。

- 目标仍是读取与后续工作的并集接近平衡。direct比较R/(E∪V)，staged比较R/(C∪E∪V)，同时输出R/(E∪V)所需的独立指标、复制与执行各自时间及重叠。
- R是该部署实测读取线程队伍的区间并集；不是将7个并发线程时间求和。C独立于R，E包含设备反量化、调度和同步，不是纯HMX算术。V不是有效计算。
- 默认平衡带为比值[1/1.02,1.02]，带内优先更多升级分片，再优先较短Tail；`--within-balance latency`可切成带内优先低延迟。片数是精度代理，并非实测质量收益。搜索为确定性多起点坐标搜索，不证明全局最优。
- 逐层0..32个Q3分片，由旧NLL重要性排名选择该层片的身份。不是全局固定Top378，也不是新激活重建误差排名。
- 每位宽保留实际验证行数对应的成本点，分段线性插值；不假设各节点恒定成本。这里的nodes是实际验证输入行数，可能含pending，不是窗口深度。
- 混合片数成本由纯位宽端点加权插值，尚未有新Q2/Q3混合内核逐层实测。旧端点的解码内核不同，新的混合调度开销可能改变预测。因此输出均为offline prediction，不是手机最优片数证明。

## 调度与内存生命周期

Draft仅允许预读L8。随后读取下一层的起点不得早于当前层执行起点。

direct：源读取直接写HTP；对应A/B槽必须等前一次使用该槽的执行完成才能覆盖。

staged：按块读普通DRAM，读完某块即可排队复制到HTP；读取下一块可与复制上一块并行。每块暂存缓冲在复制完成之前不能覆盖；任何写HTP的复制也必须等待对应A/B槽空闲。当前层全部权重复制完成后才执行。单独串行驱逐队列在计算完成后处理源缓存；最后驱逐排空单独报告，不混入比较窗口。

默认复制部署7个读取参与者、1复制worker、每协调者2×8MiB，合计14块/112MiB暂存。模型以一条“已包含7人并发效果的实测aggregate read lane”和一条copy lane模拟，不额外复制出7倍带宽。块间成本按字节分配只是近似，需回放验证。总内存预算没有建模；112MiB仅Host暂存，不能当总峰值或硬限制。

## 已有数据与缺测

direct成本：Llama3-8B、Q4 Early/aux、CPU4合批收益树、7tensor读、Tail24全流式；原纯Q2的432条generation逐层记录，纯Q3的528条，共960条。每条核对7个tensor、真实payload、实际行数、执行及7次驱逐。Q/K/FFN的具体编码由各原部署决定；不会把carrier字节当压缩读取量。共同可插值行数为6..13，范围外默认拒绝；显式`--allow-extrapolation`只会夹到端点并标记，不能认为已测出新行数曲线。

staged成本：同8B但CPU8、7读1复制，仅Q4 group32已存在648条逐层记录；实际chunk read/copy字节分别校验。原记录驱逐在读后，新调度要求计算后，政策不同；O_DIRECT下驱逐工作接近零，仍明确记录这一差异。Q2/Q3复制路径成本尚无实测，默认拒绝输出这两种位宽的最优分片数，写出calibration-required.json，绝不挪用direct成本。

## 使用

```powershell
# 使用旧排名、direct Q2/Q3，自动提取已有真实trace。输出目录需新建。
python mixed-q2q4-8b-20261021/planner/planner.py --route direct --upgrade-bit 3 --nodes 8 --output <新目录>

# 复用schema2成本表，其他实际行数：
python mixed-q2q4-8b-20261021/planner/planner.py --route direct --upgrade-bit 3 --nodes 10 --cost-table mixed-q2q4-8b-20261021/planner/multibit-final-20261024/direct-n8/cost-table.json --output <新目录>

# 复制路径先提取已有Q4成本，并输出Q2/Q3缺测清单；没有凭空规划：
python mixed-q2q4-8b-20261021/planner/planner.py --route staged --upgrade-bit 3 --nodes 8 --calibration-only --output <新目录>

# 复制路径已有Q4端点回放：
python mixed-q2q4-8b-20261021/planner/planner.py --route staged --base-bit 4 --upgrade-bit 4 --nodes 16 --output <新目录>

python -m unittest discover -s mixed-q2q4-8b-20261021/planner -p test_multibit.py
```

输出assignments.tsv有layer/shard/bits三列，不能直接送进旧两列Q4编码器；当前只是规划接口，未自动编码或部署Q2/Q3混合权重。也没有沿用旧Q4树初值去冒充Q3的新校准。PPL/Wino质量试验的固定Top378仍是独立同字节预算对照，不因本次规划而更改。

新增同路径校准应固定同一可执行文件/共享库、Early/aux、CPU线程、读取/复制线程及块大小、相同验证状态/行数，再采集纯Q2和纯Q3，以及至少一个混合片数验证点。导出与cost-table.json同schema的真实锚点后，两种路线均可直接搜索，不必手动逐一试全局Top-N。
