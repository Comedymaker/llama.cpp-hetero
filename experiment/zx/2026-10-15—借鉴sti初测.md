# 2026-10-15 借鉴 STI 初测

## 1. 实验目标与范围

借鉴 STI 的低位宽码本＋离群值保留思路，减少流式权重的存储读取量：压缩权重读入普通 DRAM，CPU 解码为 FP16，写入 HTP 共享缓冲后执行。不是将 HTP 运算改成 INT4/INT6/INT8，也不是 STI 完整系统的复现。

本次端侧性能对照为 HumanEval/000 单题，比较 4、6、8-bit 码本。尚不是完整 benchmark 平均速度，也不以输出与 FP16 完全一致作为模型质量指标。

## 2. 共同测试配置

| 项目 | 配置 |
| --- | --- |
| 原模型 | `layerskip-llama2-7B-F16.gguf` |
| Draft | CPU Early L0–L7，独立匿名 FP16 权重，4 个计算线程；未锁页 |
| Tail | HTP L8–L31，24 层全部逐层流式，无固定常驻 Tail |
| 压缩范围 | 每层 Q/K/V/O、Gate/Up/Down 共 7 个矩阵；24 层共 168 个 tensor |
| 压缩格式 | 4/6/8-bit 码本索引、FP16 码本值、离群值位置及原始 FP16 值；小参数、归一化、embedding/output head 保持原路径 |
| 分片 | 每个矩阵 32 组码本；导出文件保留原有分片及 Q/K 布局转换 |
| 在线解码 | 4 个参与线程：调用线程＋3 个持久辅助线程，处理不重叠的行范围；完成后恢复离群值 |
| HTP 运算 | 解码后的 FP16 权重；CPU/HTP 后端库和 DSP 保持不变 |
| 读取 | 1 个层读取任务线程、1 个 tensor 读取线程；O_DIRECT 读入 4096 字节对齐的压缩缓冲，无普通 buffered I/O 回退 |
| 流水线 | Q2；Draft 期间只预读 L8，进入 L8 解码后允许读 L9，之后逐层推进 |
| 缓冲 | A/B HTP 共享缓冲复用，必须同步确认本层执行结束后才可覆盖；图元数据仍需重建 |
| 缓存驱逐 | 不执行每次读取后的显式文件缓存驱逐；压缩文件通过 O_DIRECT 读取 |
| 投机 | 线性固定 w10，不建树，不启用 SSD 下一轮候选缓存 |
| 生成长度 | 先 16 token，再 128 token；屏蔽 EOS |
| 上下文/batch | `-c 2048 -b 512 -ub 128` |
| 预算参数 | memory budget 9216 MiB、runtime reserve 1536 MiB、tracked allocator cap 3600 MiB；不是 OS 强制总内存上限 |
| 绑核 | 不绑定 CPU 核 |
| 冷却 | 首轮不加 60 秒冷却，128-token 长测前冷却 60 秒，无温度门限 |
| 计时口径 | 仅生成阶段，不含 Prefill；细分时间存在重叠和嵌套，不能直接相加 |

6-bit 使用 64 项码本，4 个索引打包为 3 字节，采用对应的跨字节拆包与 NEON 查表；不是直接复用 4-bit/8-bit 索引拆包。6-bit 已通过短尾、跨字节及防越界测试，并对全部 168 个 tensor 在实际 rpcmem 中解码后进行完整 SHA 校验。

## 3. 128-token 性能汇总

| 码本位宽 | 生成时间 | 吞吐 | Draft | Tail 验证 | Correction Early | 合计采样峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 4-bit | 46.284 s | **2.766 t/s** | 16.717 s | 27.665 s | 1.489 s | 5.941 GiB |
| 6-bit | 49.035 s | **2.610 t/s** | 16.416 s | 30.638 s | 1.508 s | 5.969 GiB |
| 8-bit | 61.020 s | **2.098 t/s** | 17.479 s | 41.554 s | 1.529 s | 6.130 GiB |

6-bit 本题吞吐低于 4-bit 约 5.6%，高于 8-bit 约 24.4%。三种压缩模型的生成文本、候选数、验证轮数不同，因此这些是本题实际端到端结果，不能把全部差异归因于位宽或解码器。

### 接受情况

| 码本位宽 | Draft 候选数 | 接受候选数 | 验证轮数 | 接受数/候选数 | 接受数/(验证轮数×10) |
| --- | ---: | ---: | ---: | ---: | ---: |
| 4-bit | 264 | 102 | 27 | 38.636% | 37.778% |
| 6-bit | 264 | 101 | 28 | 38.258% | 36.071% |
| 8-bit | 284 | 100 | 29 | 35.211% | 34.483% |

最后一列是本记录的窗口接受率，不是“所有树节点的接受率”。压缩改变 Target 权重，接受率不等同于生成质量。6-bit 长测与 8-bit 输出不同，属于模型差异诊断；不能据短测输出相同推断长测也相同。

## 4. 读取、解码与执行时间

以下来自详细日志的生成阶段事件；剔除前两轮 Prefill。读取任务区间包含少量加载管理工作；纯 pread 另列。

| 指标 | 4-bit | 6-bit | 8-bit |
| --- | ---: | ---: | ---: |
| 实际压缩读取量，十进制 GB | 66.016 | 102.474 | 141.407 |
| 读取任务时间并集 | 20.709 s | 29.453 s | 39.307 s |
| 解码时间 | 13.301 s | 15.225 s | 25.080 s |
| HTP 执行至同步完成 | 12.513 s | 12.264 s | 13.654 s |
| 解码＋执行时间并集 | **25.814 s** | **27.489 s** | **38.733 s** |
| 读取 /（解码＋执行） | **0.80∶1** | **1.07∶1** | **1.01∶1** |
| 读取与解码＋执行实际重叠 | 19.805 s | 25.613 s | 35.661 s |
| 读取被覆盖比例 | 95.6% | 87.0% | 90.7% |

“HTP 执行至同步完成”包含主机调度和后端执行，不是纯 DSP 算术指令时间，也不是独立的 DRAM→SRAM 搬运时间。解码包含码本展开、FP16 写入、离群值恢复和线程协调等工作。

6-bit 的 644 对相邻层均观察到“下一层读取”与“当前层解码＋执行”重叠；不是简单将累计时间相减后推测重叠。全生成阶段读取任务 29.453 s、解码＋执行 27.489 s，两侧已接近，但不代表每层每次都完全匹配，也不代表图准备、资源释放及首尾流水线开销全部消失。

### 实际存储读取带宽口径

| 码本位宽 | 纯 pread 时间 | 实际压缩字节 / 纯 pread 时间 |
| --- | ---: | ---: |
| 4-bit | 20.458 s | 3.227 GB/s |
| 6-bit | 29.230 s | 3.506 GB/s |

6-bit 的进程存储读取计数为 102.561 GB，与实际压缩读取量 102.474 GB 接近。计数不是 UFS 设备服务时间，但本次不能解释为仅从 Page Cache 读取。

日志 `READACTIVE logical GB/s` 按还原后的 FP16 逻辑字节计算：6-bit 显示 9.234 GB/s，**不是物理存储带宽**。压缩格式之间必须使用真实压缩字节进行带宽比较，不能用 FP16 逻辑字节制造带宽提升。

## 5. 6-bit 短测、峰值及正确性控制

| 生成长度 | 时间 | 吞吐 | RSS 采样峰值 | 进程 HWM | DMA-BUF 峰值 | 合计采样峰值 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 16 token | 6.455 s | 2.479 t/s | 5.099 GiB | 5.121 GiB | 0.859 GiB | 5.958 GiB |
| 128 token | 49.035 s | 2.610 t/s | 5.110 GiB | 5.122 GiB | 0.859 GiB | 5.969 GiB |

6-bit：全部 168 个权重还原 SHA 一致；短测与长测退出码均为 0、队列失败数为 0。A/B 缓冲长测复用 2154 次，实际分配 6 次，结束后 retained bytes 为 0。16-token 输出与此前 8-bit 相同；128-token 输出不同。

合计采样峰值为同一时刻 `RSS + DMA-BUF - 已计入 RSS 的 DMA-BUF` 的最大值，不是分别取两项最大值相加。该口径不包括未映射的文件缓存与仅驱动可见的分配；匿名 Early 也未锁页，不能据此宣称严格总 DRAM 上限或永久不可换出。

6-bit 长测电池温度 33.8→34.1 °C；单次运行结果尚未给出重复实验均值或方差。

## 6. 初步结论

- 本次 6-bit 将读取与“解码＋HTP 执行”拉到约 **1.07∶1**，实际覆盖约 **87.0%** 的读取任务时间；流水线确实发生重叠。
- 4-bit 本题速度最高，但压缩模型不同、验证轮数也更少；不能仅凭速度选择位宽，还应结合独立的模型质量评估。
- 4/6/8-bit 的峰值接近，是因为在线均展开为 FP16，使用相同的 Early、KV、执行图和 A/B 工作缓冲；存储位宽降低不等于全部执行内存同比降低。
- 本结果不是“原始 FP16 直接读取”与“压缩解码”在完全相同输出轨迹下的严格加速比，也不是复现 STI 原论文的质量/性能结论。
