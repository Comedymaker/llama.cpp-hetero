# 2026-10-04 异构自投机规模化测试

## 1. 测试配置

| 项目 | 配置 |
| --- | --- |
| 模型 | `layerskip-llama2-7B-F16.gguf` |
| 测试范围 | HumanEval；6/7/9 GiB 和 8 GiB 异构批次为前 20 题，000-019 |
| 生成长度 | 每题 128 token，`--ignore-eos` |
| CPU 线程 | 4 |
| 上下文及 batch | `-c 2048 -b 512 -ub 128` |
| CPU Target | 纯 CPU `llama-completion`，mmap，单层流式缓冲 |
| 异构 Draft | CPU Early 前 8 层 |
| 异构 Tail | HTP 固定常驻权重；剩余权重直读到 HTP 共享缓冲 |
| 投机配置 | 线性窗口 10；收益树窗口 10、最多 20 节点、top-k=2 |
| 流式缓冲 | 1 个 slot；四层或混合层数 cluster |
| Prefill | 异构采用分 batch 直读路径 |
| 计时 | 仅生成阶段，不含 Prefill |
| 冷却 | 每次运行前冷却 60 秒，无温度门限 |
| 内存单位 | GiB，1 GiB = 1,073,741,824 bytes |

异构流式分组：6 GiB 为 `4,4,4,4,4,4`；7 GiB 为 `4,4,4,4,3,3`；8 GiB 为 `4,4,4,4,4`；9 GiB 为 `4,4,3,3,3`。

说明：

- 003 题第 112 个生成 token 的 ` Solution` 与 ` solution` 候选很接近，CPU 与 HTP 的 logits 排序发生翻转；无树 HTP 同前缀对照也复现。不是 EOS 或输出格式问题，具体产生差异的算子尚未定位，不能将全部吞吐提升视为正确性完全验证的加速。
