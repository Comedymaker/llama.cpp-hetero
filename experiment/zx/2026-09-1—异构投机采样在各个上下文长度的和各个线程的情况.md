# 异构投机采样在不同上下文长度和 CPU 线程数下的表现

## 实验目的

- 测量 Qwen2.5-3B Q4_0 target 模型在 CPU 4 线程和 8 线程下的 Prefill 与 Decode 吞吐，分析 CPU 线程扩展性。
- 测量 CPU draft + HTP target 异构投机采样在 128、256、512、1024 和 2048 token 上下文下的性能、接受率和阶段耗时。
- 比较 Flash Attention 开关对 CPU 基线和 CPU-HTP 异构方案的影响。
- 验证异构投机采样在什么上下文长度下能超过资源匹配的 4 线程 CPU 和更强的 8 线程 CPU 基线。

## 实验设置

- 日期：2026-09-01 至 2026-09-02。
- Target 模型：`qwen2.5-3b.q4_0.gguf`，Qwen2.5-3B，Q4_0。
- Draft 模型：`qwen2.5-0.5b.q4_0.gguf`，Qwen2.5-0.5B，Q4_0。
- Prompt：分别由 128、256、512、1024 和 2048 个 `hello` 构成的合成上下文。CPU 日志中实际 Prompt token 数与标称长度一致。
- 投机参数：`draft-max=3`，`draft-min=1`，`p-min=0.30`。

## 实验结论

- 实测结论：CPU 8 线程在五个 Depth 下均显著快于 4 线程。FA off 时，Decode 吞吐提升依次为 54.2%、49.6%、66.2%、73.5% 和 79.8%。
- 实测结论：CPU 后端开启 FA 没有表现出稳定的端到端 Decode 收益。除波动很大的 Depth 1024、4 线程结果外，其余配置基本持平或下降；在 8 线程的 Depth 1024 和 2048 下分别下降 3.1% 和 6.1%。
- 实测结论：4线程异构 FA on 组较稳定，五个 Depth 的 Decode CV 为 0.08%-2.70%；FA off 的长上下文波动明显，Depth 1024 和 2048 的 CV 分别达到 9.35% 和 14.73%。8线程异构目前只有单次结果，尚不能评价统计稳定性。
- 实测结论：4线程异构在五个 Depth 的最佳吞吐依次为 22.679、18.790、14.342、18.068 和 12.225 t/s；8线程异构的单次最佳吞吐依次为 13.804、11.797、1.365、12.057 和 11.956 t/s。8线程虽然提高 Prefill，但 Decode 均低于相同线程数的CPU基线，主要耗时增加发生在 Draft generate 和 Draft process。
- 实测结论：接受率没有随 Depth 单调下降。最佳吞吐配置下，五个 Depth 的接受率依次为 90.099%、68.595%、53.659%、82.243% 和 74.576%，Verify calls 依次为 41、49、64、44 和 43。
- 阶段性推测：上下文增长会增加 Attention/KV Cache 成本，但接受率和验证次数又取决于具体 Prompt 和生成轨迹。本次重复 `hello` 的合成输入在 Depth 1024 出现接受率回升，因此不能把这些非单调变化直接推广到自然语料。
