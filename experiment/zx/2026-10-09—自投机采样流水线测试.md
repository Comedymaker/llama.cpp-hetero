# 2026-10-09 自投机采样流水线测试

## 1. 测试配置

本记录包含 6/7/8/9 GiB 的逐层流式流水线配置：7/8/9 GiB 为末尾 Tail 常驻，6 GiB 为零常驻对照。

| 项目 | 配置 |
| --- | --- |
| 模型 | `layerskip-llama2-7B-F16.gguf` |
| 测试题目 | HumanEval/000，单题 |
| Draft | CPU Early `L0-L7`，4 个计算线程 |
| Tail | HTP `L8-L31`；末尾若干层固定常驻，其余逐层流式加载、执行 |
| 权重读取 | 常驻权重直读到 HTP 固定缓冲；流式权重直读到 HTP 共享缓冲 |
| 流水线 | 1 个读取线程；读取可与 CPU Draft、HTP 执行并行 |
| 队列容量 | 各档在结果表单列；包括准备中、读取中、已就绪及执行中的流式层，不包含常驻层 |
| 投机 | 线性 w10，不建树 |
| 生成长度 | 短测 16 token，长测 128 token，屏蔽 EOS |
| 上下文及 batch | `-c 2048 -b 512 -ub 128` |
| Prefill | Tail 分 batch 直读，最大 128 token |
| 冷却 | 每次运行前冷却 60 秒，无温度门限 |
| 计时 | 生成阶段，不含 Prefill；读取与计算存在重叠，累计时间不能直接相加 |
| 内存单位 | GiB，1 GiB = 1,073,741,824 bytes |

常驻层执行后保留权重；流式层执行完成并取出结果后释放流式资源。Q2 不表示两层权重始终已读完。


## 2. 128-token 汇总结果

| 预算 | 末尾常驻 | 流式层 | 队列容量 | 生成时间 | 吞吐 | 合计采样峰值 | 本次采样是否低于预算 | 输出校验 |

| 7 GiB | 3 层，L29-L31 | L8-L28 | 2 | 187.769 s | **0.682 t/s** | **6.997 GiB** | 是，接近上限 | 一致 |
| 8 GiB | 5 层，L27-L31 | L8-L26 | 2 | 165.684 s | **0.773 t/s** | **7.845 GiB** | 是 | 一致 |

上述各组队列均为 Q2，读取失败数为 0。均为单题结果，不是前 20 题 benchmark 平均值。

合计采样峰值 = 同一采样时刻 `RSS + DMA-BUF - 已计入 RSS 的 DMA-BUF` 的最大值，不是分别取两个峰值相加。该估计未覆盖解除映射后残留的文件缓存和仅驱动可见的分配，不是严格总 DRAM 上限证明。

## 6. cache8 的 Draft 异常定位

同一直读 R2 部署，HumanEval/000、w10、n16，开启 Early 缺页诊断；此诊断组未单独采集内存峰值。

| 配置 | 生成时间 | 吞吐 | Draft | Correction Early | Draft 主线程 major fault |
| --- | ---: | ---: | ---: | ---: | ---: |
| Draft 与读取并行 | 27.314 s | 0.586 t/s | 6.956 s | 3.759 s | 46,948 |
| Draft 期间暂停读取 | 19.934 s | 0.803 t/s | 2.169 s | 0.253 s | 0 |

两组输出一致。并行组 34 次 Draft decode 中有 3 次发生主线程 major fault，三次累计约 4.722 s；其余 31 次约 2.227 s。驻留检查发现部分 CPU Early 权重页缺失。

CPU “常驻”表示保留权重映射，不等于成功锁页、保证不会被系统回收。诊断支持并发读取期间 Early 调页会拖慢 Draft，但不代表此前全部长测波动均已归因。

## 7. 结果说明

- 本次采样低于相应预算的长测配置：6 GiB/cache0、7 GiB/cache3、8 GiB/cache5、9 GiB/cache7，队列容量均为 2。
- 9 GiB/cache8 输出正确，但采样峰值超过预算，不列为满足预算的配置。
- 当前较好单题结果为 **9 GiB/cache7 + Q2：0.975 t/s，合计采样峰值 8.691 GiB**；尚未验证完整 benchmark 的最高峰值。
- 初始末尾常驻版本保留了 CPU 源文件页，cache3 短测约 8.122 GiB；首次直读修订未实际触发直读，约 8.121 GiB。两版长测中断，不纳入上述最终汇总。
