# 2026-09-24 初步加上 Token 树

## 1. 实验目的

本阶段开始把 Token 树加入受控内存预算下的异构自投机采样。在继续比较线性窗口与 Token 树之前，先补齐 HumanEval/000-008 共 9 题的 7 GiB CPU Target 基线，用于后续计算：

1. 线性自投机相对 CPU Target 的加速比；
2. Token 树相对 CPU Target 的加速比；
3. 相同题目、相同生成长度和相同内存预算下的逐题差异；
4. Token 树增加旁支以后，接受收益能否抵消额外 Draft 节点与 Target 验证成本。

本节只记录 CPU Target 基线。Token 树各结构与阈值的完整扫描结果将在相应测试完成后继续补充，不能用当前 Target 数据单独判断 Token 树是否有效。

## 7. 005-008 的 UFS 流式读取数据

| 题目 | Layer loads | Storage reads | Prefetch time | Prefetch wait | Peak RSS |
| --- | ---: | ---: | ---: | ---: | ---: |
| 005 | 2688 | 1,087.959 GB | 470.692 s | 427.917 s | 6.644 GB |
| 006 | 2688 | 1,087.958 GB | 571.431 s | 501.476 s | 6.649 GB |
| 007 | 2688 | 1,087.958 GB | 560.331 s | 490.828 s | 6.644 GB |
| 008 | 2688 | 1,087.958 GB | 562.294 s | 490.558 s | 6.648 GB |

每个完整 128 Token 样本都累计读取约 1.09 TB 层权重。这里是重复流式读取量，不是模型文件大小。模型只有约 13 GB，但不常驻的层在每个 Token 解码时都要重新读取，因此累计 I/O 远大于模型本身。

005 的吞吐明显高于 006-008，主要差异也出现在 Prefetch 和等待时间：005 的 Prefetch wait 为 427.917 秒，而 006-008 约为 491-501 秒。这说明当前 CPU Target 的速度对 UFS/Page Cache 状态、后台 I/O 和热状态较敏感。

补测期间电池温度约为 37.9-40.8 摄氏度。006-008 的低速不能仅归因于温度，因为三题的内存规划和读取字节数基本相同，I/O 等待波动同样显著。

## 8. 对后续 Token 树实验的意义

这组 Target 基线说明，在 7 GiB 预算下，纯 CPU Target 的主要成本不是模型计算本身，而是每 Token 重复加载非常大量的非驻留层权重。后续比较线性自投机和 Token 树时，应重点记录：

1. Target 验证轮数；
2. 每轮验证的树节点数；
3. HTP preload calls、bytes 和 time；
4. Tail Verify 总时间；
5. Draft Build 时间；
6. 窗口接受率、旁支进入次数和旁支接受 Token；
7. 与 CPU Target 完全相同的最终 Token 序列。

Token 树可能通过一次 Target 调用验证多个候选路径，提高每次 Tail 权重加载的利用率；但如果旁支很少进入，额外树节点只会增加 Draft 和 Target 批处理成本。因此不能只比较接受率，最终必须比较：

\[
\text{有效输出 Token}/\text{总生成时间}
\]

并同时检查每个有效输出 Token 对应的 HTP 权重加载字节数。

## 9. 当前结论

1. HumanEval/000-008 共 9 题的 7 GiB CPU Target 基线已经补齐。
2. 000-004 复用此前完全相同配置的结果，005-008 本次补测，所有新任务均正常退出。
3. 9 题聚合 CPU Target 吞吐为 **0.1602 t/s**，后续线性窗口和 Token 树加速比应以此为统一基线。
4. 005-008 的 Peak RSS 约 6.19 GiB，符合 7 GiB 应用层内存规划。
5. 完整 128 Token 样本累计流式读取约 1.09 TB 权重，Prefetch wait 占据大量时间，说明有限内存下的绝对吞吐主要受重复 UFS 读取影响。
6. 当前结果只建立性能基线，没有执行 HumanEval 官方停止规则和 pass@1 评测，不能据此判断代码答案正确率。
7. 下一步应在同一批 000-008 Prompt 上完成线性 `window=6/8/10` 和 Token 树各结构、各阈值测试，再统一汇总吞吐、接受率、加载量与输出一致性。
