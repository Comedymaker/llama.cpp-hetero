# CNN/DailyMail 规模化测试实验配置

## 实验目的

- 将少量 Prompt 上的 CPU-HTP 异构投机采样测试扩展到 CNN/DailyMail 新闻摘要样本。
- 在统一模型、Prompt、生成长度和采样参数下，对比 CPU 4 线程、CPU 8 线程和 HTP target + CPU draft。
- 扫描投机窗口和固定置信度阈值，观察 Decode 吞吐、接受率、验证次数与阶段耗时的变化。

## 实验设置

### 1. 日期、设备和代码

| 项目 | 配置 |
| --- | --- |
| 实验日期 | 2026-09-03 至 2026-09-06 |
| 手机 | OnePlus PJZ110 |
| SoC | Qualcomm Snapdragon 8 Elite / SM8750 |
| CPU 后端 | Android CPU backend |
| NPU 后端 | Hexagon v79，设备名 `HTP0`；6 HVX、1 HMX、8 MiB VTCM |

### 2. 模型和设备分工

| 角色 | 模型 | 量化 | 执行设备 |
| --- | --- | --- | --- |
| Target | Qwen2.5-3B，`qwen2.5-3b.q4_0.gguf` | Q4_0 | CPU 基线使用 CPU；异构组使用 HTP0 |
| Draft | Qwen2.5-0.5B，`qwen2.5-0.5b.q4_0.gguf` | Q4_0 | CPU |



### 3. 数据集和 Prompt

- 数据集：CNN/DailyMail 3.0.0 test split。
- 数据源：Hugging Face `abisee/cnn_dailymail` 的 Parquet 文件。
- 数据划分：test。
- shuffle seed：`221117192`。
- 过滤条件：文章按空白字符切分后为 400 至 1400 个词。
- 从过滤后的乱序数据中选择前 100 篇，编号为 `cnn_dm_00` 至 `cnn_dm_99`。
- 规模化实验使用 `cnn_dm_00` 至 `cnn_dm_79`，共 80 篇。
- 窗口和 `p-min` 扫描使用 `cnn_dm_00` 至 `cnn_dm_19`，共 20 篇。

Prompt 模板：

```text
Summarize the following news article in three concise bullet points. Only include information supported by the article.

Article:
{article}

Summary:
```


### 4. 统一推理参数

| 参数 | 设置 | 说明 |
| --- | ---: | --- |
| 请求生成长度 | `-n 128` | 固定长度吞吐测试 |
| Context | `-c 4096` | 覆盖筛选后的长文章 Prompt |
| Batch | CPU 基线 `-b 128`；异构组 `-b 2048` | 异构程序要求 batch 容纳完整 Prompt，早期 `-b 128` 会报 Prompt 超过 batch |
| Ubatch | `-ub 128` | 所有对照保持一致 |
| KV cache | F16 | K/V 均使用默认 F16 |
| 采样 | `--temp 0 --top-k 1` | Greedy，保证同一 Prompt 的 token 路径稳定 |
| EOS | `--ignore-eos` | 强制完成固定长度输出 |
| Target 层 | `-ngl 99` | 异构组 target 下沉 HTP0 |
| Draft 层 | `-ngld 0` | Draft 留在 CPU |
| Draft 类型 | `--spec-type draft-simple` | 自回归小模型 draft |
| Draft 最小长度 | `--spec-draft-n-min 1` | 所有异构组一致 |

固定 `-n 128 --ignore-eos` 用于对齐 Decode 工作量和接受率统计，不代表自然 EOS 下的摘要长度，也不用于 ROUGE 或生成质量评价。CPU `llama-cli` 通常报告 127 次 eval；投机程序可能因最后一批验证越过边界而实际输出 129 至 133 token。聚合吞吐必须按总 token 除以总时间计算，不能直接平均逐样本 t/s。

### 5. 实验矩阵

| 实验 | 样本 | 配置 | 重复次数 |
| --- | ---: | --- | ---: |
| CPU 4 线程 target-only | 80 | `t=4` | 1 |
| CPU 8 线程 target-only | 80 | `t=8` | 1 |
| 投机窗口扫描 | 20 | `draft-max=1,2,3,4,8,16`，`p-min=0.30` | 每个窗口 3 |
| 最优窗口全量复核 | 80 | `draft-max=4`，`p-min=0.30` | 1 |
| `p-min` 扫描 | 20 | `draft-max=4`，`p-min=0,0.1,0.2,0.3,0.4` | 每个阈值 3 |
| `p-min` 全量复核 | 80 | `draft-max=4`，实际完成 `p-min=0,0.2,0.3` | 每个阈值 1 |

窗口和阈值的 20 篇扫描用于选参，80 篇运行用于规模化复核。

### 6. 运行环境

异构组每次新开 shell 后设置：

```sh
cd /data/local/tmp/llama.cpp-hetero

LIBDIR="$PWD/lib"
export LD_LIBRARY_PATH="$LIBDIR:$PWD/bin:$PWD/hetero-lib:$PWD"
export ADSP_LIBRARY_PATH="$LIBDIR;/vendor/dsp/cdsp;/vendor/lib/rfsa/adsp;/system/lib/rfsa/adsp"
export CDSP_LIBRARY_PATH="$ADSP_LIBRARY_PATH"
export DSP_LIBRARY_PATH="$LIBDIR:$PWD"
unset GGML_HEXAGON_NDEV
export GGML_HEXAGON_DEVICES=1

./bin/llama-bench --list-devices
```

只有日志出现 `HTP0 new session` 且设备列表包含 `HTP0` 后才运行异构实验。`error 0x80000406` 表示 HTP session 未建立，该次结果无效。

CPU 基线使用独立 CPU-only 目录：

```sh
cd /data/local/tmp/llama.cpp-cpu
export LD_LIBRARY_PATH="$PWD:$PWD/lib"
```

### 7. CPU target-only 基线命令

CPU 4 和 CPU 8 线程仅改变 `T`，其余参数保持一致。这里保留原始 CPU 基线的 `-b 128`：

```sh
EXP=/data/local/tmp/llama-exp-cnndm
PROMPTS=/data/local/tmp/llama-exp-hetero/prompts/cnn_dm
TARGET=/data/local/tmp/llama.cpp-cpu/qwen2.5-3b.q4_0.gguf
mkdir -p "$EXP/cpu_t4/results" "$EXP/cpu_t4/logs" "$EXP/cpu_t8/results" "$EXP/cpu_t8/logs"

for T in 4 8; do
    for I in $(seq -w 0 79); do
        ID="cnn_dm_$I"
        sleep 60

        ./llama-cli \
            -m "$TARGET" \
            -f "$PROMPTS/${ID}.txt" \
            -n 128 -c 4096 \
            -b 128 -ub 128 \
            -t "$T" -ngl 0 \
            --temp 0 --top-k 1 \
            --ignore-eos \
            > "$EXP/cpu_t${T}/results/${ID}.txt" \
            2> "$EXP/cpu_t${T}/logs/${ID}.log"
    done
done
```


### 8. CPU-HTP 异构投机命令模板

```sh
cd /data/local/tmp/llama.cpp-hetero

EXP=/data/local/tmp/llama-exp-cnndm
PROMPTS=/data/local/tmp/llama-exp-hetero/prompts/cnn_dm
TARGET=/data/local/tmp/llama.cpp-cpu/qwen2.5-3b.q4_0.gguf
DRAFT=/data/local/tmp/llama.cpp-cpu/qwen2.5-0.5b.q4_0.gguf
mkdir -p "$EXP/hetero/results" "$EXP/hetero/logs"

run_hetero() {
    ID="$1"
    WINDOW="$2"
    PMIN="$3"
    TAG="$4"

    ./bin/llama-speculative-simple \
        -m "$TARGET" \
        -md "$DRAFT" \
        --spec-type draft-simple \
        -dev HTP0 -ngl 99 \
        -devd none -ngld 0 \
        -f "$PROMPTS/${ID}.txt" \
        -n 128 -c 4096 \
        -b 2048 -ub 128 \
        -t 4 \
        --threads-draft 4 \
        --threads-batch-draft 4 \
        --spec-draft-n-max "$WINDOW" \
        --spec-draft-n-min 1 \
        --spec-draft-p-min "$PMIN" \
        --temp 0 --top-k 1 \
        --ignore-eos \
        -fa off \
        > "$EXP/hetero/results/${TAG}.txt" \
        2> "$EXP/hetero/logs/${TAG}.log"
}
```

窗口扫描：

```sh
for R in 1 2 3; do
    for W in 1 2 3 4 8 16; do
        for I in $(seq -w 0 19); do
            ID="cnn_dm_$I"
            TAG="window${W}_${ID}_r${R}"
            sleep 60
            run_hetero "$ID" "$W" 0.30 "$TAG" || exit $?
        done
    done
done
```

窗口 4 全量复核：

```sh
for I in $(seq -w 0 79); do
    ID="cnn_dm_$I"
    TAG="window4_p030_${ID}"
    sleep 60
    run_hetero "$ID" 4 0.30 "$TAG" || exit $?
done
```

`p-min` 扫描：

```sh
for R in 1 2 3; do
    for P in 0.00 0.10 0.20 0.30 0.40; do
        for I in $(seq -w 0 19); do
            ID="cnn_dm_$I"
            PTAG=$(echo "$P" | tr -d '.')
            TAG="window4_p${PTAG}_${ID}_r${R}"
            sleep 60
            run_hetero "$ID" 4 "$P" "$TAG" || exit $?
        done
    done
done
```

### 9. 温控、后台运行与恢复

- 每个样本运行前至少冷却 60 秒。
- 运行前后记录 `dumpsys battery` 中的 temperature；Android 通常以 0.1 摄氏度为单位报告该字段。
- 若温度高于 380，即 38.0 摄氏度，则每 60 秒重新检查，降至阈值以内再开始。


### 10. 统计指标

每个 CPU 样本从 `llama-cli` 日志提取：

- Prompt token 数和 prompt eval time。
- Decode eval 次数和 eval time。
- total time。

每个异构样本从 `llama-speculative-simple` 日志提取：

- `encoded` token、耗时和吞吐。
- `decoded` token、耗时和吞吐。
- `n_drafted`、`n_accept` 和 `accept`。
- `phase target decode`。
- `phase draft generate`。
- `phase draft process`。
- `phase verify calls`。

统一统计公式：

```text
聚合 Prefill 吞吐 = 所有 Prompt token 总数 / 所有 Prefill 时间总和
聚合 Decode 吞吐 = 所有实际输出 token 总数 / 所有 Decode 时间总和
加权接受率 = sum(n_accept) / sum(n_drafted)
每次验证接受 token = sum(n_accept) / sum(verify_calls)
每次验证产出 token = sum(decoded_token) / sum(verify_calls)
阶段占比 = 对应阶段总时间 / Decode 总时间
```

三轮扫描应同时报告每轮聚合吞吐、三轮均值、样本标准差和变异系数。全量结果应报告样本数、总 token、聚合吞吐、逐样本均值、标准差、中位数、最小值和最大值。
