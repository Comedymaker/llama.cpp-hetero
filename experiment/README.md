# 实验记录说明与样例

本目录用于按时间线记录端侧异构融合推理实验。每次实验单独保存为一个 Markdown 文档，避免把不同设备、模型、后端或评测口径混在同一结论中。

## 命名规则

- 已知日期：`YYYY-MM-DD—实验名.md`
- 跨多日实验：文件名使用实验开始日期，完整日期范围写在“实验设置”中。
- 日期未知：`日期待确认—实验名.md`，不要根据文件修改时间推断实验日期。
- 实验名应简短并能区分核心变量，例如：`2026-06-03—CPU与NPU并行验证扩展性.md`。
- 使用全角破折号 `—` 分隔时间和实验名；日期统一补齐为两位月、日，以便文件按名称排序。

## 结构规则

每份实验记录固定包含以下四个二级标题，顺序不可变：

1. `## 实验目的`
2. `## 实验设置`
3. `## 实验结果`
4. `## 实验结论`

填写时遵守以下原则：

- “实验目的”说明本次要验证的问题或假设，不提前写成已经成立的结论。
- “实验设置”记录日期、设备、模型、量化格式、后端、参数、数据集、重复次数和命令；未记录的信息明确写“原始记录未注明”。
- “实验结果”优先保留原始数值和异常现象；不同程序或不同量化格式的数据要说明不能严格横向比较。
- “实验结论”区分实测结论、阶段性推测和待验证问题，不把局部算子加速直接写成端到端收益。
- 单位保持一致；吞吐默认使用 `t/s` 或 `tok/s`，时间注明 `ms` 或 `s`。

## 样例

复制下面的内容创建新文档，并替换所有占位项。

```markdown
# 实验名称

## 实验目的

- 验证……
- 对比……

## 实验设置

- 日期：YYYY-MM-DD
- 设备：设备型号 / SoC
- 模型：Target 模型；Draft 模型（如适用）
- 量化格式：
- 后端：CPU / GPU / NPU
- 数据集或 Prompt：
- 关键参数：`n_prompt=...`，`n_gen=...`，`ctx=...`，`draft-max=...`
- 重复次数：
- 代码版本：commit SHA 或分支名
- 原始日志：相对路径或链接

## 实验结果

| 模式 | Prefill 吞吐 | Decode 吞吐 | 接受率 | 峰值内存 | 备注 |
| --- | ---: | ---: | ---: | ---: | --- |
| 基线 | 待填写 | 待填写 | 不适用 | 待填写 |  |
| 实验组 | 待填写 | 待填写 | 待填写 | 待填写 |  |

记录异常、误差范围、运行次数和不可直接比较的条件。

## 实验结论

- 实测结论：……
- 阶段性推测：……
- 局限：……
- 下一步：……
```
