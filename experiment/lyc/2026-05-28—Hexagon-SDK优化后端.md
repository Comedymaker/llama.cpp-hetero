# Hexagon SDK 优化后端

## 实验目的

评估基于 Hexagon SDK 的优化 NPU 后端在不同模型规模下的 prefill 和逐 token decode 性能，并与 CPU 基线对比。

## 实验设置

- 日期范围：2026-05-28 至 2026-05-29
- 后端：MyHTP / NPU；CPU 对照
- 模型规模：约 0.5B 和 3B
- 5 月 28 日量化：IQ4_NL + Q8_0，494.03M 参数
- CPU/NPU 对比使用的量化格式不完全相同
- 设备、完整模型文件名、运行命令、重复次数和代码版本：原始记录未注明

## 实验结果

### 2026-05-28：0.5B 量级模型

| 后端 | 模型/量化 | Prefill pp512 | Decode tg32 |
| --- | --- | ---: | ---: |
| MyHTP | IQ4_NL + Q8_0，494.03M | 1962.56 ± 53.36 t/s | 21.48 ± 1.31 t/s |

原始表格标记为“qwen2 1B”，但参数量为 494.03M，指令和前后文均对应 Qwen2.5-0.5B；此处按 0.5B 量级记录。

### 2026-05-29：CPU/NPU 对比

| 后端 | 0.5B pp128 | 0.5B tg64 | 3B pp128 | 3B tg64 |
| --- | ---: | ---: | ---: | ---: |
| CPU | 127.444 | 52.963 | 17.541 | 10.027 |
| NPU | 1328.442 | 22.279 | 408.256 | 6.436 |

- NPU 的 0.5B/3B prefill 分别约为 CPU 的 10.4x/23.3x。
- NPU 逐 token decode 仍弱于 CPU：0.5B 约为 CPU 的 42%，3B 约为 64%。

## 实验结论

- 优化后的 NPU 后端在 prefill 上表现出显著优势，但逐 token decode 仍弱于 CPU。
- 该特征支持把 NPU 用于粗粒度、规则且计算密集的工作负载，例如 prefill 或批量验证，并保留 CPU 处理低并行度 decode 的可能性。
- 由于 CPU/NPU 使用的量化格式不完全相同，这组数据适合说明运行特征，不应视为严格的纯后端加速比。
