# CPU-only 投机采样初测

## 实验目的

验证端侧 CPU-only 投机采样能否利用高速 draft 模型和较高接受率获得相对 target-only 的端到端加速。

## 实验设置

- 日期范围：2026-04-28 至 2026-04-29
- 后端：CPU-only
- 4 月 28 日：短 Prompt；模型名称和设备在原始记录中未注明
- 4 月 29 日：CNN/DailyMail；Qwen3-0.4B draft + Qwen3-4B target
- 两个模型均完整载入内存，llama.cpp 层面没有权重 offloading
- 量化格式、生成长度、线程数、重复次数和代码版本：原始记录未注明

## 实验结果

### 2026-04-28：短 Prompt

| 指标 | 结果 |
| --- | ---: |
| Target 单跑 | 8.59 tok/s |
| Draft 单跑 | 75.88 tok/s |
| 接受率 | 58.5% |
| 理论加速比 | 约 1.7x |
| 实测加速比 | 0.82x |

单跑较快的 draft 没有转化为投机采样收益。

### 2026-04-29：CNN/DailyMail

| 模式 | 吞吐 |
| --- | ---: |
| Draft 单跑 | 49.42 t/s |
| Target 单跑 | 15.21 t/s |
| 标准投机采样 | 10.53 t/s |
| 接受率 | 45.161% |

- 投机采样比 target-only 慢约 30.8%。
- 模型组合没有达到手机内存上限，不能将慢速主要归因于权重换入或换出。
- 同配置云端结果：draft 412.05 t/s、target 97.54 t/s、投机采样 93.065 t/s、接受率 53.3%。

## 实验结论

- 当前 CPU-only 配置未获得端到端加速，理论加速和 draft 单跑速度不足以预测实际收益。
- 云端同配置也未超过 target-only，说明当时的实现或参数设置仍需排查，不能把手机端慢速完全归因于端侧硬件。
