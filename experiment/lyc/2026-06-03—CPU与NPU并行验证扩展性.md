# CPU 与 NPU 并行验证扩展性

## 实验目的

比较 CPU target 与 NPU target 在不同 draft window 下的批量验证扩展性，解释异构投机采样收益的来源。

## 实验设置

- 日期：2026-06-03
- 对比组合：CPU target + CPU draft；NPU target + CPU draft
- `draft-max`：1、2、4、8
- 模型、设备、量化格式、Prompt、生成长度、重复次数和代码版本：原始记录未注明

## 实验结果

| Target/Draft | Draft-max | Spec 吞吐 | 接受率 | Target 验证吞吐 |
| --- | ---: | ---: | ---: | ---: |
| CPU target + CPU draft | 1 | 8.903 t/s | 85.714% | 11.84 t/s |
| CPU target + CPU draft | 2 | 9.173 t/s | 89.583% | 11.93 t/s |
| CPU target + CPU draft | 4 | 8.275 t/s | 76.562% | 12.23 t/s |
| CPU target + CPU draft | 8 | 6.574 t/s | 65.909% | 11.22 t/s |
| NPU target + CPU draft | 1 | 12.748 t/s | 88.571% | 17.44 t/s |
| NPU target + CPU draft | 2 | 16.284 t/s | 93.478% | 23.23 t/s |
| NPU target + CPU draft | 4 | 19.470 t/s | 81.250% | 34.24 t/s |
| NPU target + CPU draft | 8 | 20.039 t/s | 70.000% | 44.53 t/s |

- CPU target 验证吞吐始终约为 11-12 t/s，甚至低于当时记录的 CPU target-only decode 14.15 t/s。
- NPU target 验证吞吐随 `draft-max` 从 1 增长到 8，由 17.44 t/s 增至 44.53 t/s；接受率降至 70% 时，整体吞吐仍达到最高的 20.039 t/s。

## 实验结论

- 在当前模型、后端和窗口设置下，CPU 未获得可扩展的批量验证收益，而 NPU 获得了明显收益。
- 当前实现中，CPU 与 NPU 的关键差异是批量验证扩展性；这解释了 CPU draft + NPU target 能获得正收益的重要机制。
- 该结论仅适用于本次配置，不应外推为所有 CPU/NPU 实现都必然如此。
